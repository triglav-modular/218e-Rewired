218e v3 Rewired — firmware builder

Custom v36.9 firmware for the Buchla 218e, built in your browser.

⚠ READ THIS BEFORE YOU FLASH ANYTHING

This is only for the Buchla 218e version 3, running firmware v36.9. Not the 218, not the 218r, not the 218e v1 or v2, not any other touchplate controller. The build refuses any file that is not the exact v36.9 image.

You do this entirely at your own risk. This is experimental, unofficial firmware, not made or supported by Buchla. It has been tested on one instrument. It can brick your keyboard. Recovering a bricked unit may need JTAG hardware and opening the instrument, and may not be possible at all.

A failed flash usually leaves the keyboard in DFU mode, where the flasher can try again — but nobody is promising that. If losing the use of your 218e would be a problem, stop here and keep the factory firmware.

2 · Options

Volts per octave — 1.2 is the standard Buchla scaling. 1 V/oct is for other gear. The 208 needs retrimming after a change.

3 · Alternate tunings optional

Three tuning tables, switched from edit mode. Each Scala file needs 12 degrees and a true 2/1 octave. Empty slots keep the factory temperament.

Each scale is shifted so A sits at the same pitch in every slot — the shift is shown per slot — so switching tuning never means retrimming the 208. Which degree lands on the bottom C is up to the file: a scale published rooted on A needs rotating first.

all three slots factory

4 · Per-key pitch correction optional

Corrects your 208's tracking per semitone, so the keyboard plays in tune across its range. Enter what your tuner reads: how many cents sharp each note played — positive sharp, negative flat. The builder works out the correction; do not negate anything yourself.

Every 208 is different, so there is no useful default and this starts at zero. Measurements only apply at the volts-per-octave you took them at.

How to measure your 208 — read this first

1. Set the volts per octave. Match the setting above to how your 208 is trimmed, and leave it there. A table measured at one scaling is wrong at the other.

2. Warm up for at least 30 minutes. The oscillator drifts as it comes up to temperature, often by more than the error you are correcting.

3. Tune the lowest C. Octave switch at its lowest setting, hold the lowest C, and trim the 208 until a tuner reads it exactly in tune. Everything else is measured against this note.

4. Play every note, note how far off it is. Work up from that C, changing octave as you run out of keys. Enter the tuner reading in cents — +12 for 12 cents sharp, −7 for 7 flat.

5. Build, flash, check. Nothing accumulates: each box is just what that note measured. To redo it, turn the correction off, measure again, and retype.

Measure against equal temperament — an alternate tuning's own intervals would read as error.

One-time setup

Windows — the WinUSB driver
Windows will not let dfu-programmer reach the keyboard until the DFU device is bound to WinUSB. The flasher opens Zadig for you at the point the device is visible. In Zadig: if the list looks empty, turn on Options → List All Devices, select AT32UC3B DFU (USB ID 03EB 2FF6), then Install Driver. It can pause for several seconds before starting. Once per machine.
The tools themselves ship with this package — nothing extra to download.
macOS on Apple silicon — Rosetta
dfu-programmer is x86_64 only:
softwareupdate --install-rosetta
Both — your system will warn about unsigned software
On macOS this is avoidable: get the package with git clone rather than downloading the ZIP, and there is no warning at all. A browser download marks every file as quarantined; a clone does not.
If you did download it, macOS blocks the flasher and then dfu-programmer as being from an unidentified developer — open System Settings → Privacy & Security and press Open Anyway for each. The flasher spots the second one itself and offers to clear it. Windows Defender may warn about the .bat: More info → Run anyway.
  1. Download the image above. Leaving it in Downloads is fine.
  2. Connect the 218e, directly rather than through an unpowered hub:
    Standalone LEM218 — USB-C to the computer, power connected, switched on.
    218e module — USB-B from the 5xIO module that carries its USB and MIDI.
  3. Run the flasher and follow it:
    macOS — double-click Program218e_v3_Rewired.command
    Windows — double-click Program218e_v3_Rewired.bat
If something goes wrong
The keyboard is stuck in DFU and will not come back as MIDI
If nothing was erased, the flasher tells you so and prints the command that boots it again. A power cycle on its own may not be enough: once the fuses have been read, ISP_FORCE is set and the instrument returns to DFU until it is told to start.
macOS: mac/support/dfu-programmer at32uc3b1256 start
Windows: windows\support\dfu-programmer.exe at32uc3b1256 start
Every LED is lit and the keyboard does nothing
There is no valid firmware on it — an erase happened but the write did not finish. Run the flasher again; it will find the instrument in DFU and complete the job.
Windows: no device present, or Device Manager lists AT32UC3B DFU under Other devices
The WinUSB driver is not bound. Run Zadig as above. Installed correctly, the entry moves to Universal Serial Bus devices.
Windows: the 218e appears under Universal Serial Bus devices instead of Sound, video and game controllers
Windows has picked the wrong MIDI driver, so the DFU request never reaches the instrument. Right-click it, Update driver, choose manually, and pick USB Audio Device.
Windows: VCRUNTIME140_1.dll was not found, or a tool is "not recognized"
The Microsoft C++ runtime is missing. Install it from Microsoft's redistributable page, or from Buchla's kit.
Removing the driver Zadig installed
Rarely needed. pnputil /enum-drivers in a Command Prompt, find the entry mentioning at32uc3b or libusb, note its oemNN.inf, then as Administrator: pnputil -f -d oemNN.inf
The flasher finds the image itself — it checks firmware/, its own folder and Downloads, and takes whichever file matches the checksum it expects. Nothing to move or rename.

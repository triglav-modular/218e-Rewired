218e Rewired

Custom firmware builder for the Buchla 218e V3

⚠ READ THIS BEFORE YOU FLASH ANYTHING

This firmware is for the Buchla 218e V3 only. It won't work on the 218, the 218r, the 218e V1 or V2, or any other touchplate controller.

Using this tool and firmware is entirely at your own risk. This is an experimental, unofficial firmware, not made or supported by Buchla. Flashing this will probably void your warranty. It has been tested on one instrument. Recovering a bricked unit may need JTAG hardware and opening the instrument, or may not be possible at all.

A failed flash usually leaves the keyboard in DFU mode, where the flasher can try again, but there is no guarantee that it will succeed. If losing the use of your 218e would be a problem, stop here and keep the factory firmware.

How to measure your 208. Read this first!

1. Set the volts per octave. Match the setting above to how your 208 is trimmed, and leave it there. A table measured at one scaling is wrong at the other. Measure against equal temperament.

2. Warm up for at least 30 minutes. The oscillator drifts as it comes up to temperature, often by more than the error you are correcting.

3. Tune the lowest C. Octave switch at its lowest setting, hold the lowest C, and trim the 208 until a tuner reads it exactly in tune. Everything else is measured against this note.

4. Play every note, note how far off it is. Work up from that C, changing octave as you run out of keys. Enter the tuner reading in cents. For example, +12 for 12 cents sharp, −7 for 7 cents flat.

5. Build, flash, check.

Alternate tunings

Three tuning tables, switched from edit mode. Each Scala file needs 12 degrees and a true 2/1 octave. Empty slots keep the factory temperament.

Each scale is shifted so A sits at the same pitch in every slot so switching tuning doesn't need retuning. Which degree lands on the bottom C is up to the file: a scale published rooted on A needs rotating first.

4 · Flash it

  1. Download and extract the built package for your operating system.
  2. Connect the 218e, directly rather than through an unpowered hub:
    Standalone LEM218 — USB-C to the computer, power connected, switched on.
    218e module — USB-B from the 5xIO module that carries its USB and MIDI.
  3. Power on the 218e.
  4. Run the flasher and follow their instructions:
    macOS — a download is quarantined and unsigned, so macOS blocks it.
    Dequarantine the whole folder in Terminal:
    xattr -dr com.apple.quarantine <the unzipped folder>
    then double-click Program218e_v3_Rewired_macOS.command.
    Windows — double-click Program218e_v3_Rewired_Windows.bat

Your system might warn you about unsigned software

If you skipped the xattr command above and macOS blocks the flasher, open System Settings → Privacy & Security and press Open Anyway. Control-clicking and choosing Open does not work.
Windows Defender may warn about the .bat: More info → Run anyway.

Windows only — the first flash pauses for a driver

Partway through the flash, the flasher will stop and open Zadig at the one moment it can see the device. Do the following steps in it:

  1. Options → List All Devices
  2. Select AT32UC3B DFU
  3. Set the right-hand box to WinUSB, press the Install Driver or Replace Driver button
  4. Close Zadig.
Oh no… something went wrong

What the keyboard is doing

Some LEDs are lit and the keyboard ignores you
It is still in DFU mode, waiting. Run the flasher again, or bring it back with the ExitDFU script for your platform:
ExitDFU_218e_v3_macOS.command
ExitDFU_218e_v3_Windows.bat
Every LED is lit and nothing responds
There is no valid firmware on it: the erase finished and the write did not. Run the flasher again. The instrument stays in DFU for exactly this reason.

Windows: the wrong driver is bound

The flasher says no device present, or AT32UC3B DFU sits under Other devices
WinUSB is not bound to the DFU device. Run Zadig as above. Once it is right, the entry moves to Universal Serial Bus devices.
The 218e sits under Universal Serial Bus devices instead of Sound, video and game controllers
Windows picked the wrong MIDI driver, so the request to enter DFU never reaches the instrument. Right-click it, Update driver, choose manually, and pick USB Audio Device.
